Artificial intelligence inference runs a trained model to generate outputs from new input. Unlike training, it executes a fixed model efficiently in real time or near-real time. As models have grown to hundreds of billions of parameters, fast and cost-effective inference has become one of the central engineering problems in the field.

Large language models such as GPT, LLaMA, Qwen, and DeepSeek are autoregressive transformers: they process the input through a series of attention and feed-forward layers, produce a probability distribution over the vocabulary, select the next token, append it to the context, and repeat until a stopping criterion is met. This sequential decode phase is fundamentally memory-bandwidth-bound, because at every step the model must read all of its weights from memory just to produce a single output token.

The vLLM framework introduced PagedAttention, which maps logical KV-cache pages to non-contiguous physical memory blocks, analogous to virtual memory paging, cutting fragmentation and raising memory utilization. Continuous batching, also called iteration-level scheduling, inserts new requests into the running batch as soon as slots free up, keeping the hardware busy and improving throughput. Quantization to INT8, INT4, or FP8 lowers memory-bandwidth requirements and lets more parameters fit on a device. Grouped-query attention reduces the number of key-value heads, shrinking the KV cache that must be read on each decode step. On Ascend NPUs, the CANN compiler fuses normalization, quantization, attention, and activation operators into compound kernels for higher roofline efficiency.

Key-value cache management is central to performance: as context length grows, the KV cache can consume gigabytes of memory per request, so prefix caching reuses the cache for shared prompts and hierarchical offloading moves cold entries to slower memory tiers. Performance is judged by several metrics at once: throughput in output tokens per second, time to first token which is dominated by the prefill phase, and time per output token during the memory-bound decode phase. Each of these is sensitive to batch size, sequence length, and hardware configuration, so benchmarking must match the target deployment scenario.
